# 锅炉效率计算服务

燃煤电厂性能试验用后端：每个班次同时用**正平衡**（输入-输出法）和**反平衡**（热损失法）
计算锅炉效率，自动对账找出差值最可能来自哪个测量，全部结果版本化，月度加权汇总，
已发布月度值以修订说明方式追踪变化。

- Python 3.12 / FastAPI / PostgreSQL 16
- 计算为纯函数模块，持久层只负责版本存储，接口层只做编排

## 模块划分

| 模块 | 职责 |
|---|---|
| `app/combustion.py` | 燃烧计算：理论空气量、烟气量、过量空气系数、气体焓 |
| `app/direct.py` | 正平衡效率 |
| `app/indirect.py` | 反平衡各项热损失（q2–q6） |
| `app/reconcile.py` | 对账：加权最小二乘调整、首要怀疑对象 |
| `app/engine.py` | 编排：运行数据+煤质+配置 → 完整结果（纯函数） |
| `app/repository.py` | 版本库：输入版本、结果版本、月度汇总与修订 |
| `app/api.py` / `app/main.py` | FastAPI 接口层与装配 |
| `app/validation.py` | 领域校验（拒收并指出字段） |

## 计算口径

基准：1 kg 收到基燃料；气体体积为标准状态（0 °C、101.325 kPa）体积。

**理论空气量**（元素为收到基质量百分数）：

```
V0 = 0.0889·(C + 0.375·S) + 0.265·H − 0.0333·O   [Nm³/kg]
```

纯碳时为 8.89 Nm³/kg（有单元测试锁定）。烟气量（RO2、N2、H2O、过量空气部分）
由元素分析按常规工程公式推出，见 `combustion.py` 注释。

**过量空气系数**取干烟气近似并做 CO 修正：`α = 21 / (21 − (O2 − 0.5·CO))`。
O2=0 且 CO=0 时 α=1（有测试锁定）。

**反平衡**：`η = 100 − (q2+q3+q4+q5+q6)`

- q2 排烟热损失：干烟气与水蒸气相对环境温度的焓差，气体平均容积比热容取
  0–300 °C 工程拟合式（`combustion.py` 中有系数与出处说明）；
- q3 化学不完全燃烧：干烟气中 CO 体积 × CO 发热量（12636 kJ/Nm³，可配置）；
- q4 机械不完全燃烧：灰渣残碳 `灰分 × Σ 份额·C/(100−C)` × 纯碳发热量
  （32866 kJ/kg，可配置）——飞灰含碳为零时只剩炉渣部分（有测试锁定）；
- **q5 散热损失（设计决定）**：默认取**固定值** 0.5%（配置 `radiation_loss.mode=fixed`）；
  也可切换为按额定负荷折算 `q5 = q5e × De/D`（`mode=load_curve`）。
  取固定值为默认是因为试验班组通常按规程给定值，负荷曲线法作为可选项保留；
- q6 灰渣物理热损失：飞灰按排烟温度、炉渣按排渣温度（默认 600 °C，可配置）
  的显热，灰渣比热容默认 0.96 kJ/(kg·K)。

**正平衡**：输出 = 主蒸汽吸热 + 再热蒸汽吸热 + 排污水相对给水的热量
（排污水焓取汽包压力饱和水，默认 1400 kJ/kg，可配置）；输入 = 入炉煤量 × 收到基低位发热量。

## 对账（设计决定）

设 `g(x) = η_正(x) − η_反(x)`，求调整量 δ 使 `g(x+δ) = 0` 且 δ 相对各自
不确定度最小——**加权最小二乘**（权 1/σ²）。标量约束下的最小范数解
`δ = −g·ΣJ/(JᵀΣJ)`（Σ=diag(σ²)，J 为数值梯度），即每个测量分摊的调整量
正比于其方差与对差值的灵敏度：**越测不准、越影响差值的测量，分得越多**。
因效率非线性，用高斯-牛顿迭代到 |g| < 1e-9，保证调整后两法真正一致。

判定与报告：

- `|g| ≤ 容差`（默认 0.5 个百分点，可配置）→ `consistent`，**调整量为零**；
- 所有 `|δ_i| ≤ k·σ_i`（k 默认 3，可配置）→ `adjusted`，返回调整后测量值；
- 任一 `|δ_i| > k·σ_i` 或迭代不收敛 → `exceeds_uncertainty_budget`：
  仍返回最小范数解、各调整的 σ 倍数和首要怀疑对象，但明确标记**超出不确定度
  预算，需人工核查**，而不是硬凑一组不可信的数。

首要怀疑对象 = `|δ_i|/σ_i` 最大的测量。不确定度按测量逐项配置
（相对读数百分比或绝对值），默认值见 `app/config.py`。

## 版本化与并发

- 运行数据、煤质、配置各自只追加不改写，版本号递增；任何一方变化都在
  **同一事务**内重算并产生新结果版本，结果记录所依据的运行数据版本、
  煤质版本、配置版本；旧版本可按 `?version=N` 取回。
- 煤质未到的班次结果状态为 `pending_assay`，只报"待化验"，不给效率。
- 配置变更（不确定度、容差等）产生新配置版本，并用新配置重算全部班次。
- **并发**：写操作先对班次行 `SELECT ... FOR UPDATE`，同一班次的并发写入
  串行化，后提交的事务能看到先提交的全部输入——化验与运行数据改正同时到达时，
  最终最新版本必然同时基于两者，不会停留在只反映一方的中间状态
  （有并发测试锁定）。两者同批到达时可用 `POST /shifts/{id}/data`
  一次提交，只产生一个结果版本。

## 月度汇总

- 月度效率按班次**输出热量加权**汇总，正、反平衡分别给出；
  每次重算后由当前全部最新结果**从头汇总**（`math.fsum` 保证逐位一致），
  因此存储的月度值与任何时刻从头汇总的结果完全一致（有测试锁定）。
- `POST /monthly/{month}/publish` 发布：冻结发布值并对当时各班次结果做快照。
  发布后数据再变，**发布值不改写**，当前值照常更新，同时生成修订说明
  （前后正/反平衡值 + 引起变化的班次及各自新旧结果版本）。

## 数据校验（拒收并指出字段，HTTP 422）

元素质量分数之和与 100% 偏差 > 0.5 个百分点（`elemental_sum`）、发热量不为正
（`qnet`）、排烟氧量超出 0–21%（`flue_o2`）、主蒸汽焓不大于给水焓
（`main_steam_enthalpy`）、灰渣份额之和不为 1（`fly_ash_share`）、
不确定度不为正（配置校验，Pydantic 字段路径）等，见 `app/validation.py`。

## 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/shifts/{id}/run-data` | 录入/改正运行数据（新版本 + 重算） |
| POST | `/shifts/{id}/coal-quality` | 录入/复检煤质（新版本 + 重算） |
| POST | `/shifts/{id}/data` | 两者同批提交（单个结果版本） |
| GET | `/shifts/{id}/result[?version=N]` | 最新/指定版本结果 |
| GET | `/shifts/{id}/results` | 全部结果版本及输入版本 |
| POST | `/config` | 新配置版本（重算全部班次） |
| GET | `/config` | 当前配置 |
| GET | `/monthly/{YYYY-MM}` | 月度当前值与发布值 |
| POST | `/monthly/{YYYY-MM}/publish` | 发布月度值 |
| GET | `/monthly/{YYYY-MM}/revisions` | 修订说明列表 |

## 运行

```bash
docker compose up --build     # app: python:3.12-slim 镜像, db: postgres:16-alpine
```

应用启动时自动等库、建表、写入默认配置（v1）。`DATABASE_URL` 环境变量覆盖连接串。

## 测试

```bash
pip install -r requirements-dev.txt
pytest                      # 单元 + 集成（集成测试需要一个 PostgreSQL 16）
```

集成测试默认使用 `/workspace/.pg` 下的 PostgreSQL 16 二进制（可用 `PG_BIN`
环境变量指向其他安装）；测试库每次用例前清空并重建默认配置。

覆盖：纯碳理论空气量、零氧量过量空气系数、排烟温度/飞灰含碳趋势、两法一致
零调整、燃煤量偏差指向燃煤量、煤质迟到与复称重算、月度与从头汇总一致、
已发布月度修订说明、并发到达不产生中间版本、各校验拒收场景。
